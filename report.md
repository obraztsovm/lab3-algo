### Теоретическая часть

Использование статических структур данных накладывает жесткие ограничения на гибкость программного обеспечения, так как размер памяти для них должен быть известен еще на этапе компиляции. Для преодоления этих ограничений применяются динамические структуры данных, размер которых может изменяться в процессе выполнения программы в зависимости от объема входящих данных. В рамках данной работы были исследованы и реализованы две фундаментальные концепции: динамический массив (`Vector`) и односвязный список (`GenericList`).

Динамический массив хранит свои элементы в непрерывном блоке оперативной памяти. Главным преимуществом такой организации является константное время доступа к элементам по индексу $O(1)$ за счет прямой адресации. Однако при исчерпании выделенного объема (`capacity`) требуется операция реаллокации памяти — выделение нового блока (обычно в 2 раза больше прежнего) и покомпонентное копирование туда старых данных. Для оптимизации расходов памяти также применяется обратный процесс: уменьшение емкости буфера при значительном удалении элементов из структуры.

Односвязный список, напротив, представляет собой упорядоченный набор узлов, разбросанных по куче (`heap`). Каждый узел содержит информационное поле и указатель на следующий элемент. Доступ по индексу здесь требует последовательного перебора элементов с головы списка, что занимает линейное время $O(n)$, но добавление элементов в начало или удаление текущего узла при наличии прямой ссылки выполняется за стабильное константное время $O(1)$.

Особенностью данной работы является проектирование *обобщенных (generic)* контейнеров на языке Си. Поскольку в Си отсутствуют встроенные шаблоны (как в C++), универсальность достигается за счет использования нетипизированных указателей `void *`, хранения размера одного элемента `elem_size` в байтах и применения механизма *глубокого копирования (deep copy)* через системные вызовы `memcpy` и `memmove`. Для реализации логики поиска и фильтрации обобщенных данных в структуру передаются указатели на пользовательские функции-компараторы (`EqualsFunc`), инкапсулирующие правила сравнения конкретных типов.

### Результаты задач 1–2 (Динамический вектор и его операции)

Разработанная библиотека динамического вектора полностью реализует автоматическое управление выделенной памятью. Вспомогательная функция `needToResize` контролирует заполненность вектора, инициируя расширение буфера при `size >= capacity` или его сжатие до `capacity / 2`, если количество элементов падает ниже 25% от зарезервированного пространства. Это позволяет держать баланс между скоростью работы и объемом используемой памяти.

Функция добавления `appendVectorItem` выполняет копирование переданного указателя на глубину `elem_size` байт в соответствующее смещение массива `byte_ptr + size * elem_size`. Прямое чтение и перезапись по индексу выполняются в функциях `getVectorItem` и `setVectorItem`, снабженных обязательной проверкой на выход за пределы выделенных границ (`index >= size`).

Особое внимание уделено функции `popVectorItem`. При удалении элемента из середины массива для сохранения непрерывности структуры применяется функция `memmove`. Она сдвигает хвост массива влево на один шаг (`elem_size` байт), перезаписывая удаляемый элемент. Освобожденная ячейка копируется во вновь выделенную область памяти на куче и возвращается пользователю, который берет на себя ответственность за её последующее освобождение через `free()`. Функция поиска `findVectorItem` последовательно проходит по байтовому буферу и вызывает пользовательский компаратор `cmp`, возвращая индекс первого совпадения.

### Результаты задач 3–5 (Использование структур для прикладных задач)

На базе универсальных интерфейсов вектора и списка были успешно решены три прикладные задачи обработки гетерогенных структур данных.

В **Задаче 1 (Поиск студента)** была создана структура `Student`, содержащая текстовое поле фиксированной длины и вещественный балл. Элементы последовательно добавлялись в обобщенный контейнер, после чего функция `findMaxStudent` линейным проходом по узлам списка выявила запись с наибольшим значением `avg`, корректно извлекая данные из нетипизированных указателей `void *`.

В **Задаче 2 (Нахождение максимума в массиве)** была реализована универсальная функция `findMaxVector`. Благодаря абстракции над типами, передаче размера элемента и использованию различных функций сравнения (`intGreater`, `longGreater`, `floatGreater`), одна и та же функция успешно справилась с поиском экстремумов в целочисленных массивах (`int`, `long`) и массивах с плавающей точкой (`float`).

В **Задаче 3 (Удаление дубликатов)** были реализованы алгоритмы очистки контейнеров от повторяющихся элементов с сохранением исходного порядка их первого появления:
* Для списка (`removeDuplicatesList`) применен метод «бегущего указателя». При обнаружении дубликата ссылки в узлах перестраивались в обход удаляемого элемента, после чего память из-под данных `runner->data` и самого узла `runner` корректно очищалась.
* Для вектора (`removeDuplicatesVector`) очистка выполнена по месту (*in-place*) без выделения дополнительного буфера. Элементы, не являющиеся дубликатами, перезаписывались в начало того же массива со смещением `newSize`, после чего внутренний счетчик элементов `vector->size` принудительно уменьшался. Сравнение текстовых строк производилось через специализированный строковый компаратор.
